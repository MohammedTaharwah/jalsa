# منصة "جلسة" - Multiplayer Q&A Platform

بنية تحتية متكاملة وقابلة للتوسع لمنصة أسئلة وأجوبة تفاعلية متعددة اللاعبين تعتمد على الحاويات باستخدام **Docker Compose**.

---

## 🏗️ الخدمات المتضمنة (Services Architecture)

| الخدمة | التقنية | المنفذ (Port) | الوصف |
| :--- | :--- | :--- | :--- |
| **قاعدة البيانات** | PostgreSQL 16 (Alpine) | `5433` (خارجي) / `5432` (داخلي) | تخزين بيانات المستخدمين، الجلسات، الأسئلة، والنتائج مع Healthcheck مدمج |
| **الخلفية (Backend)** | FastAPI (Python 3.11) | `8000` | واجهات REST API + دعم WebSockets للغرف التفاعلية المتزامنة |
| **الواجهة (Frontend)** | React 18 + Vite | `5173` | واجهة المستخدم مع خاصية Hot Module Replacement المباشرة |
| **الذكاء الاصطناعي** | n8n Workflow & AI Agents | `5678` | أتمتة وإدارة وكلاء الذكاء الاصطناعي (AI Agents) لتوليد المحتوى وتحليل الإجابات |

## 🗄️ جداول قاعدة البيانات (SQLAlchemy Models)

1. **جدول `users`:**
   - `id`: المعرف الفريد للمستخدم (Primary Key).
   - `username`: اسم المستخدم الفريد (Unique Index).
   - `email`: البريد الإلكتروني الفريد.
   - `hashed_password`: كلمة المرور المشفرة بتقنية bcrypt.
   - `balance`: رصيد النقاط (Balance/Points) للمسابقات واستخدام المساعدات.
   - `created_at`: وقت وتاريخ التسجيل.

2. **جدول `categories`:**
   - `id`: المعرف الفريد للتصنيف.
   - `name`: اسم التصنيف (مثل: رياضة، تاريخ، علوم، تكنولوجيا).
   - `description`: وصف التصنيف.
   - `created_at`: تاريخ الإنشاء.
   - علاقة ترابطية مع جدول الأسئلة (`questions`) مع خاصية الحذف المتتالي (Cascade Delete).

3. **جدول `questions`:**
   - `id`: المعرف الفريد للسؤال.
   - `category_id`: معرف التصنيف (Foreign Key -> categories.id).
   - `question_text`: نص السؤال.
   - `options_json`: مصفوفة الخيارات بصيغة JSON.
   - `correct_answer`: الإجابة الصحيحة.
   - `points_level`: عدد النقاط / مستوى الصعوبة (افتراضي 100).
   - `media_url`: رابط وسائط داعمة (صورة/صوت إن وجد).
   - `status`: حالة السؤال (active, draft, archived).
   - `created_at`: تاريخ الإضافة.

4. **جدول `powerups`:**
   - `id`: المعرف الفريد للمساعدة.
   - `name`: اسم المساعدة (مثل: حذف إجابتين، تجميد الوقت، مضاعفة النقاط).
   - `description`: شرح الميزة.
   - `cost`: تكلفة الشراء من رصيد النقاط (Cost in points).
   - `created_at`: تاريخ الإنشاء.

## 🔒 المصادقة والأمان (JWT Authentication)

- **التسجيل:** `POST /auth/register` (إنشاء مستخدم جديد وتشفير كلمة المرور).
- **تسجيل الدخول:** `POST /auth/login` (إرجاع JWT Bearer Token).
- **توافق Swagger UI:** `POST /auth/token` يتيح تجربة الحماية مباشرة عبر زر `Authorize` في Swagger.
- **الملف الشخصي:** `GET /auth/me` (محمي ويتطلب Bearer Token).

## 🤖 ربط وتكامل الذكاء الاصطناعي مع n8n (AI Agent Integration)

### 1. إرسال أمر التوليد (`POST /api/admin/generate-questions`):
يقوم الـ Admin بتحديد اسم الفئة وعدد الأسئلة والمستوى، ليرسل الـ Backend طلباً إلى Webhook خادم n8n على:
`http://n8n:5678/webhook/generate-questions`

**نموذج جسم الطلب (Request Body):**
```json
{
  "category_name": "علوم وفضاء",
  "count": 5,
  "difficulty": "medium",
  "language": "ar"
}
```

### 2. استقبال الأسئلة وحفظها (`POST /api/webhooks/n8n-receive`):
يقوم وكيل الذكاء الاصطناعي في n8n بمعالجة الطلب، وتوليد الخيارات، وتحديد الإجابة الصحيحة ورابط الوسائط، ثم إرسالها إلى الـ Backend.

**طبقة الأمان (Header API Key):**
يجب تضمين المفتاح السري التالي في الترويسات (Headers) لمنع أي تلاعب:
```http
X-N8N-API-KEY: jalsah_n8n_secret_token_2026
```

**نموذج الحمولة المستقبلة من n8n (Payload Sample):**
```json
{
  "category_name": "علوم وفضاء",
  "questions": [
    {
      "question_text": "ما هو أقرب كوكب إلى الشمس؟",
      "options_json": ["عطارد", "الزهرة", "المريخ", "المشتري"],
      "correct_answer": "عطارد",
      "points_level": 100,
      "media_url": "https://example.com/mercury.png"
    }
  ]
}
```
*يتم حفظ كافة الأسئلة المستقبلة مباشرة في قاعدة بيانات PostgreSQL بالحالة الافتراضية:* `status: "pending"` *لتتيح للمشرفين مراجعتها واعتمادها للألعاب.*

## 🎮 محرك اللعبة التفاعلي (Local Multiplayer / Shared Screen Engine)

تم بناء محرك اللعبة باستخدام **React** و **Tailwind CSS** مع إدارة حالة شاملة عبر **Context API** لدعم نمط اللعب الجماعي على نفس الشاشة:

### 1. معالج إعداد الجلسة المتطور (Game Setup Wizard - 4 Steps):
تمت إعادة بناء شاشة الإعداد بالكامل لتعتمد على ثيم فاتح ومشرق (`Off-white: bg-slate-50`) وظلال ملونة ناعمة مع مكتبة `framer-motion` وحركات سلسة بين 4 خطوات:
- **شعار المنصة الرسمي (Logo):** استيراد الشعار ووضعه في منتصف الشاشة مع تأثير عائم أنيق.
- **الخطوة 1 - الفرق (Teams):** إضافة وتعديل من فريقين إلى 4 فرق مع أيقونات احترافية من `lucide-react` (Shield, Flame, Zap, Crown).
- **الخطوة 2 - الفئات (Categories):** شبكة بطاقات تفاعلية أنيقة لاختيار مجالات الأسئلة (رياضة، تاريخ، علوم، سينما، ثقافة، تقنية، جغرافيا، فنون) مع إطار برتقالي جذاب وعلامة Check عند التحديد.
- **الخطوة 3 - إعدادات الجولة (Settings):** اختيار عدد الأسئلة (10، 20، 30) مع أزرار تبديل تفاعلية (Toggle Switches) لتفعيل الأسلحة والمؤقت.
- **الخطوة 4 - الملخص والانطلاق (Summary & Launch):** بطاقة ملخص استعراضية متكاملة وزر كبير متدرج من البرتقالي للأرجواني **"ابدأ التحدي الآن 🚀"**.

### 2. ساحة المواجهة المشتركة (The Battleground Board - Jeopardy Style):
- **شبكة الفئات والمستويات:** تتكون اللوحة من 6 فئات رئيسية بمستويات نقاط (**200**، **400**، **600** نقطة).
- **غزو الفئات والمنافسة التكتيكية:** كل فريق يمتلك 3 فئات تمثل نقطة قوته، ويمكن للفريق الآخر في دوره اختيار سؤال من فئة الخصم لحرمانه من نقاطها وتخريب خطته!
- **حالة المربعات:** عند الإجابة على أي مربع، يتم إغلاقه ووسمه بشارة الفريق الفائز بنقاطه.

### 3. مربعات الحظ المخفية وعجلة الحظ (Mystery Tiles & Wheel of Fortune 🎡):
- تم إخفاء عجلة الحظ خلف 3 مربعات عشوائية في اللوحة.
- عند فتح مربع حظ سري، تظهر شاشة **"عجلة الحظ والمفاجآت"** التفاعلية لتدور وتحدد مصير السؤال:
  1. **⚡ ضاعف النقاط (x2 Points):** مضاعفة نقاط السؤال للفريق.
  2. **🔄 تحويل السؤال للمنافس (Pass to Rival):** انتقال إجباري للسؤال إلى الفريق الخصم للإجابة عليه!
  3. **🧠 بدون خيارات (No Choices - 3x Points):** تحدي الذاكرة للإجابة بدون خيارات مقابل 3 أضعاف النقاط!
  4. **⚠️ فخ الخصم (Penalty Trap):** خصم نقاط السؤال في حال الإجابة الخاطئة!
  5. **🎁 هدية ذهبية (Safe Bonus):** سؤال آمن مع 100 نقطة إضافية مضمونة.
  6. **🎯 حذف خيارين (50:50):** استبعاد خيارين خاطئين تلقائياً.

### 4. زر الريمونتادا والمواجهة المباشرة (The Comeback Mode 🔥):
- ميزة حماسية لا تظهر إلا في الثلث الأخير من التحدي، وفقط للفريق المتأخر بفارق كبير (600 نقطة أو أكثر).
- يظهر زر ناري متوهج: **"🔥 زر الريمونتادا (المواجهة المباشرة: 1000 نقطة)!"**.
- يراهن الفريق بكل عزيمته على سؤال واحد صعب؛ إما أن يعود بقوة ويقلب الطاولة للصدارة، أو يخسر الرهان!

### 5. منصة التتويج والنهاية (Podium & Victory):
- عند انتهاء جميع مربعات اللوحة، يتم الانتقال إلى منصة التتويج مع مفرقعات احتفالية وتحديد الفريق البطل.

## 🚀 طريقة التشغيل (Quick Start)

### 1. التأكد من وجود ملف المتغيرات البيئية
ملف `.env` جاهز ومضبوط مسبقاً، وإذا أردت تخصيص كلمات المرور أو المنافذ يمكنك تعديله مباشرة.

### 2. تشغيل الحاويات (Build & Run)
قم بتشغيل الأمر التالي في سطر الأوامر (Terminal / PowerShell) داخل مجلد المشروع:

```bash
docker-compose up --build
```

أو لتشغيله في الخلفية (Detached mode):

```bash
docker-compose up -d --build
```

## 🚀 النشر المجاني على Render + Neon/Supabase

### Backend على Render

- اختر **Root Directory**: `backend`.
- استخدم **Build Command**: `pip install -r requirements.txt`.
- استخدم **Start Command**: `uvicorn main:app --host 0.0.0.0 --port $PORT`.
- أضف متغيرات البيئة من `.env.example`، خصوصاً `DATABASE_URL` مع `sslmode=require`، و`JWT_SECRET_KEY`، وبيانات SMTP، و`CORS_ORIGINS` التي تحتوي رابط الواجهة المنشورة.

يوجد ملف `backend/Procfile` لنفس أمر البدء عند استخدام إعدادات Render المعتمدة على Procfile.

### Frontend على Render

- استخدم **Root Directory**: `frontend`.
- استخدم **Build Command**: `npm run build`.
- استخدم **Publish Directory**: `dist`.
- اضبط `VITE_API_URL` على رابط خدمة Backend في Render.

لا تضع كلمات المرور أو مفاتيح PayPal أو مفاتيح SMTP داخل Git؛ استخدم Environment Variables في Render وNeon/Supabase.
